# Bem-vindo ao Blog Tempest

Abrimos este espaço para compartilhar, em público, o que aprendemos construindo
serviços e bibliotecas no Projeto Tempest. Aqui vão aparecer decisões de
arquitetura, receitas que funcionam em produção e os tropeços que nos fizeram
mudar de ideia.

<!-- more -->

## Por que um blog?

Boa parte do que sabemos mora em PR, issue e conversa de time — lugares onde
quase ninguém de fora consegue achar. Escrever em público força a gente a
explicar o **porquê**, e devolve para a comunidade um pouco do que recebemos
dela.

## Sobre o que vamos escrever

| Tema | Exemplos |
| --- | --- |
| **Backend — Python** | o [`tempest-fastapi-sdk`](https://pypi.org/project/tempest-fastapi-sdk/), nosso framework de backend: FastAPI async-first, camadas router → controller → service → repository, SQLAlchemy 2.0, Pydantic v2 |
| **Frontend — JavaScript** | o [`tempest-react-sdk`](https://www.npmjs.com/package/tempest-react-sdk), nosso framework de frontend: componentes, hooks e integrações para React |
| **Arquitetura e decisões** | quando implementar em vez de depender de uma lib, como evitar que um aviso na doc vire bug em produção |
| **Visão computacional** | classificação, detecção e segmentação no servidor e no browser com o [`ort-vision-sdk`](https://pypi.org/project/ort-vision-sdk/) |

## Um gostinho

Todo projeto nosso começa pelos dois SDKs:

=== "Backend (Python)"

    ```bash
    uv add "tempest-fastapi-sdk[auth,postgres]"
    ```

    Só os extras que o serviço usa — cada dependência opcional é carregada
    sob demanda.

=== "Frontend (JavaScript)"

    ```bash
    npm install tempest-react-sdk
    ```
